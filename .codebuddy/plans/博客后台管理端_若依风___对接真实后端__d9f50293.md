## 用户需求

在现有 Vue3 个人博客前端中新增一个「登录后才能进入」的后台管理端，对接已存在的若依风格 Spring Boot 后端（D:/lzkgit/my_blog_bak，端口 8080），并参考若依后台的接口与布局规范进行设计；视觉上沿用博客现有的简洁黑白风格，而非若依默认蓝色主题。

## 产品概述

后台管理端是一套面向博主的内容运营控制台：用户使用账号密码登录后，进入若依风格的管理框架（左侧动态菜单 + 顶部导航栏 + 面包屑 + 用户下拉菜单），在框架内对各业务数据进行增删改查与查看。所有菜单与权限由后端按角色动态下发，前端 100% 动态渲染，后端返回什么就展示什么。

## 核心功能

- 账号密码登录（JWT），未登录访问后台自动跳转登录页；登录态持久化（localStorage）。
- 登录后拉取用户信息（权限集合）与动态菜单树，自动构建左侧导航与路由。
- 若依风格管理框架：可折叠左侧菜单、顶部导航（面包屑、全屏、主题切换、用户下拉、退出登录）。
- 仪表盘：欢迎信息 + 关键内容统计卡片。
- 个人中心：展示当前账号、权限，提供退出登录。
- 21 张业务表的通用 CRUD 视图：列表展示、按列筛选、新增/编辑（弹窗表单）、删除（确认）；无 `blog:{资源}:edit` 权限时自动转为只读。

## 重要边界说明

后端 `sys_menu` 初始化数据仅包含内容类模块（21 张业务表），未提供若依标准的「系统管理（用户/角色/菜单/日志）」菜单与接口。因此本次以「动态菜单 + 21 资源通用 CRUD + 仪表盘 + 个人中心」为完整可运行范围；若后续需要系统管理，需后端先补充对应端点，前端侧边栏天然兼容（动态渲染，无需改动）。

## 技术栈

- 前端：Vue 3 + TypeScript + Element Plus + Pinia + Vue Router 4 + Vite（与现有项目完全一致，不引入新框架）
- 后端对接：HTTP 经 Vite 开发代理 `/api` → `http://localhost:8080`（避免跨域凭据问题，复用现有 `baseURL: '/api'`）
- 已有依赖可直接复用：`axios`（请求封装）、`nprogress`（路由进度条）、`dayjs`（时间格式化）

## 实施方案

### 总体策略

在现有前端工程中「平行扩展」一套 `/admin` 子系统：登录页 + 管理框架布局 + 动态路由 + 通用 CRUD。鉴权、菜单、权限全部以真实后端为准，前端不做硬编码菜单。通用 CRUD 采用「单一组件 + 资源字段 schema 配置」方案，21 个资源共用一个 `CrudView`，由路由 `meta.resource` 与 `src/views/admin/crud/schema.ts` 驱动表格列与表单字段，最大限度减少重复代码。

### 关键技术决策

1. **动态路由 vs 静态路由**：若依标准做法是后端返回菜单树、前端动态 `addRoute`。本后端已提供 `GET /api/auth/menus`（含 `component`、`path`、`menuType`、`perms`），完全契合动态路由。叶子菜单（menuType=C）统一映射到一个通用 `CrudView`，`meta.resource` 由 `perms` 反推（`blog:project:edit` → `project`），无需为每个资源写独立页面，扩展性最佳。
2. **资源字段 schema（核心抽象）**：后端通用 CRUD 不返回字段元信息（类型/中文名/选项），前端在 `schema.ts` 中集中声明 21 个资源的字段（label、类型、是否表格列、是否表单字段、选项、图片/状态标记等）。该配置同时驱动表格渲染与表单生成，是「配置驱动」而非「组件堆叠」，新增资源只需加一条配置。
3. **请求层增强而非重写**：保留现有 `request.ts` 的响应拆包（`res.code===200` → `res.data`），仅补充：请求拦截器注入 `Authorization: Bearer <token>`；响应拦截器对 `code===401` 做登出跳转；登录接口 `data` 即 token 字符串，与现有拆包逻辑天然兼容。
4. **权限只读降级**：`CrudView` 依据 `userStore.hasPerm('blog:'+resource+':edit')` 控制新增/编辑/删除按钮显隐，无权限时表格仍可查看——与后端 403 校验形成前后端双重防护。
5. **无后端分页**：`/api/admin/{resource}` 返回全量 `List`，列表在客户端做简单筛选与排序，数据量（个人博客）可接受，避免引入与后端不一致的分页协议。

### 性能与可靠性

- 菜单/信息仅在登录与刷新时拉取一次，路由构建后缓存；`CrudView` 列表按需加载（进入路由才请求），避免无谓请求。
- token 失效（401）统一在响应拦截器处理，防止页面卡死。
- 字段 schema 为静态配置，零运行时开销；表格使用 Element Plus 虚拟滚动友好的基础表格即可满足个人站点量级。

## 实施要点（防回归）

- 复用现有 `src/utils/request.ts` 与 `src/store` 的 Pinia 写法（如 `useAppStore` 的 `ref/computed` 风格），不要另起状态范式。
- 修改 `vite.config.ts` 仅追加 `server.proxy`，不要改动现有 `baseURL` 默认值（`/api`），以免影响现有公开站点接口。
- 导航守卫需区分「公开站点 `/`」与「后台 `/admin`」，不破坏现有博客展示页路由。
- 401 跳转登录页前清空 token 与动态路由，避免死循环。
- 使用 [skill:lsp-code-analysis] 在改动 `router/index.ts`、`request.ts`、`store` 前核对现有确切签名与导出方式，避免路径/导入错误。

## 关键代码结构（配置与契约）

```ts
// src/views/admin/crud/schema.ts —— 资源字段配置契约
export type FieldType = 'text' | 'textarea' | 'number' | 'switch' | 'select' | 'image' | 'link' | 'datetime'
export interface FieldSchema {
  key: string
  label: string
  type: FieldType
  table?: boolean      // 是否在列表展示
  form?: boolean       // 是否出现在表单
  width?: number
  options?: { label: string; value: string | number }[] // 用于 select/switch/status
  required?: boolean
}
export interface ResourceSchema {
  resource: string     // 对应后端资源名，如 'project'
  title: string        // 模块中文名
  fields: FieldSchema[]
}
// 导出 Record<string, ResourceSchema>，以资源名为键，共 21 条
```

// src/router/index.ts —— 动态路由 meta 约定

  }

## 设计风格

采用「若依布局骨架 + 博客极简黑白皮肤」的融合方案：保留若依后台的核心结构（左侧可折叠菜单 + 顶部导航栏 + 面包屑 + 用户下拉 + 内容卡片），但去除若依默认蓝色，全面沿用博客现有的纯黑白配色、圆角、dark/light 自动主题与柔和过渡动画，营造高级、克制、现代的运营控制台气质。面向桌面端（Web），非移动端放大版。

## 页面规划（4 屏）

### 1. 登录页（/admin/login）

- 块1 背景层：浅灰渐变/细网格背景，中心浮起登录卡片，柔和投影与入场动画。
- 块2 品牌区：站点名 + 一句话标语，极简无冗余装饰。
- 块3 表单卡片：账号/密码输入框（带图标）、登录按钮（加载态）、错误提示，圆角与聚焦描边动效。
- 块4 页脚声明：版权/备案等弱提示文字。

### 2. 后台框架（AdminLayout：侧边栏 + 顶栏 + 内容区）

- 块1 左侧菜单栏：可折叠，目录/菜单分层，el-icon 图标，选中态用黑色描边/浅灰高亮，hover 微动效。
- 块2 顶部导航栏：左为折叠按钮 + 面包屑；右为全屏、主题切换、用户头像下拉（个人中心/退出）。
- 块3 内容页头：当前模块标题 + 描述。
- 块4 主内容区：承载仪表盘 / 通用 CRUD / 个人中心，统一卡片容器与过渡。

### 3. 通用 CRUD 页（CrudView）

- 块1 筛选工具条：关键字/状态等列筛选输入 + 查询/重置按钮（依据 schema）。
- 块2 操作工具条：新增按钮（无权限时隐藏）、刷新、导出（可选）。
- 块3 数据表格：列由 schema 驱动；状态/布尔用 Tag/Switch 展示；图片/封面列显示缩略图预览；操作列含编辑/删除。
- 块4 表单弹窗：新增/编辑共用 el-dialog + el-form（由 schema 生成输入/文本域/数字/开关/下拉/图片上传占位）。

### 4. 仪表盘（Dashboard）

- 块1 欢迎横幅：问候语 + 当前账号名 + 日期。
- 块2 统计卡片网格：文章数、作品数、音乐数、分类数等关键指标（圆角卡片 + 数字动效）。
- 块3 快捷入口：常用模块跳转卡片。
- 块4 最近动态/提示区：空态或轻量信息展示。

### 5. 个人中心（Profile）

- 块1 账号卡片：头像占位 + 用户名 + 用户ID。
- 块2 权限列表：当前 permissions 标签展示。
- 块3 操作区：退出登录按钮。
- 块4 安全提示：令牌为无状态 JWT、前端仅作展示等说明。

## 交互与响应式

- 桌面优先；侧边栏 ≥1280px 默认展开，<1280px 默认折叠可手动展开。
- 统一 8–12px 圆角、1px 浅灰描边、hover/选中微过渡（沿用博客 transition 风格）。
- 路由切换使用与现有站点一致的淡入位移过渡。
