# Backend Requirements: 个人作品集站点（my_blog_）后端数据需求

> 说明：这份文档描述的是**前端要什么数据**，不是规定后端怎么做。
> 下面出现的所有"建议路径 / 字段名"都只是沟通起点，路径、方法、命名、拆合完全由后端决定，欢迎直接推翻。

## Context

- 项目是一个个人作品集 / 博客站点（Vue 3 + Vite + Pinia + Element Plus），面向**站点访客**，纯只读展示，目前**没有任何登录鉴权**。
- 现有 4 个页面：`/dashboard`（主页）、`/portfolio`（作品）、`/articles`（文章）、`/contact`（联系），全部共享同一布局（导航栏 + 页脚 + 右下角音乐播放器）。
- 站点支持**中英双语切换**和**深色/浅色主题**（主题是前端本地状态，不需要后端）。
- 当前**所有内容都硬编码在前端** `src/data/*.ts` 里（home / projects / articles / music / navigation / contact / education …），一个请求都没发。
- 已准备好的请求层：`src/utils/request.ts`（axios 实例，`baseURL = import.meta.env.VITE_BASE_API || '/api'`，超时 10s，响应拦截器里判断 `res.code !== 200` 就 `ElMessage.error(res.msg)` 并 reject）。
- 目标：把内容搬到后端，让作品 / 文章 / 歌单 / 联系方式可以在后台维护，前端不再改代码发版。

---

## 通用约定（前端侧已经这么写了，后端可推翻）

| 事项 | 前端现状 / 期望 |
|------|----------------|
| 响应包装 | 拦截器读 `code`，非 200 就弹 `msg`。所以约定 `{ code, msg, data }`，成功 `code = 200`。若后端改用 HTTP 状态码语义，请保证 `code` 字段仍然存在且成功值为 200，否则我要改拦截器 |
| 超时 | 10s |
| 语言 | 前端有全局 `language: 'zh' \| 'en'`，存在 localStorage |
| 图片 / 音频 | 目前前端直接用外链（微信图片 CDN、Figma、picsum）和本地静态资源 `/music/...`。图片标签统一带了 `referrerpolicy="no-referrer"`（因为微信图片有防盗链） |
| 鉴权 | 站点侧接口预期全部匿名只读。若后台管理是独立系统，与本站接口分离即可 |

## Screens / Components

### 1. 导航栏（全站，`src/layout/components/SidebarNav.vue`）

**Purpose**：顶部固定导航，滚动后变胶囊毛玻璃样式；含 Logo、页面菜单、语言切换、主题切换。

**Data I need to display**
- 导航菜单列表：每项需要一个**稳定标识**（当前是 `dashboard` / `portfolio` / `articles` / `contact`）和**随语言变化的显示文案**。
- 菜单的**显示顺序**希望可由数据决定（现在是前端写死 4 项）。

**Actions**
- 点击菜单 → 纯前端路由跳转，**不需要接口**。
- 语言 / 主题切换 → 纯前端本地状态，**不需要接口**。

**States to handle**
- 当前页高亮由前端路由状态决定，不需要后端字段。
- 菜单拉取失败：目前无降级方案，建议前端保留一份静态兜底菜单（想听后端意见是否值得做）。

**Business rules affecting UI**
- 菜单标识与前端路由名一一对应（首字母大写）。若后端返回的标识变了，前端必须同步改，请尽量固定。

### 2. 页脚（全站，`src/layout/index.vue`）

**Data I need to display**
- 版权署名文案（目前写死 `© 2026 刘中魁`）。
- 设计声明文案（`Powered by …`，中英各一份）。

**建议**：这两项和导航、首页文案一样都属于"站点配置"，希望并入一个全局配置接口，而不是单独开接口。

### 3. 主页 Dashboard（`src/views/dashboard/index.vue` + `PortfolioGrid`）

**Purpose**：Hero 大标题 + 右侧联系卡片 + 精选作品网格。点击 Hero 标题可就地筛选作品分类。

**Data I need to display**
- **Hero 区**：一组"大标题项"，每项 = 主文案 + 右侧灰色注释 + 一个**关联的作品分类（可为空）**。
  - 分类为空时，点击不筛选，而是弹一个 toast（"还在学… 🍳"）。
  - ⚠️ 特殊情况：文案里含"摄影摄像 / Photography & Videography"的项，前端会**硬拆成"摄影""摄像"两个可点区域**分别跳分类。这是前端的 hack，最好后端别返回这种合并文案，或者我们约定拆分规则。
- **个人简介**：一段多行文本，前端按 `|` 切分换行。
- **精选作品区**：区块标题 + 年份范围字符串（形如 `[ 2024 — 2026 ]`）。
- **右侧联系卡片**：BASE 标签、所在地文案、hover 时的气泡提示文案、"取得联系"链接文案。
- **作品网格**：项目列表（结构见下方"作品 / Project"实体），需能按分类筛选。

**Actions**
- 点击 Hero 标题 → **前端本地筛选已加载的作品**，不重新发请求。
- 点击"取得联系" → 跳转到联系页。
- 点击作品卡片 → 打开详情弹窗（见下方第 4 节）。

**States to handle**
- **Loading**：首屏 Hero 文案 + 作品列表同时拉取。
- **Empty**：某个分类下没有作品 —— 前端作品网格目前**没有空态**，需要补，也请后端保证"分类列表"和"实际有数据的分类"一致。
- **Error**：作品列表拉失败时，是整页报错还是只在网格区域局部提示？我倾向局部错误提示，请后端给建议。
- **Special**：点击无分类的 Hero 标题 → toast 提示（文案前端本地写死，除非要运营可配）。

**Business rules affecting UI**
- Hero 项关联的分类必须是作品分类枚举内的值，否则点击后筛选结果为空。
- 作品分类枚举当前是 5 个：`All` / `Photography` / `Videography` / `Graphics & UI` / `Development`（另有 `Article` 只用于文章页，不出现在作品页）。

### 4. 作品页 Portfolio（`src/views/portfolio/index.vue`、`PortfolioGrid.vue`、`ProjectDetailModal.vue`）

**Purpose**：作品列表 + 分类筛选 + 详情弹窗 + 图片灯箱。同一套网格组件也被主页复用。

**Data I need to display**
- 页面标题 + 描述（中英）。
- **作品（项目）列表**，每个项目需要：
  - 稳定 id
  - 分类：`Photography` / `Videography` / `Graphics & UI` / `Development`
  - 封面图地址（**可为空**）
  - 可选媒体与外链（都可为空）：直链视频地址、**B 站 BV 号**、Figma 链接、线上 Demo 网址、GitHub 仓库地址
  - 开发类专用：**图标标识**（当前取值 `message-circle` / `id-card` / `file-text` / `film`，缺省回退通用图标）、技术栈副标题
  - **图集**：多张图片地址（摄影类在详情弹窗里做画廊，点开进灯箱）
  - 双语文本：标题、副标题、描述、角色、标签数组、获奖列表、设计意图 / 创意陈述、职责详情
- **分类筛选栏**：需要"当前可用的分类列表"及其**中英文案**（现在是前端按数据自己算的，也可以后端下发）。
- 目前的中文案映射：全部 / 静态摄影 / 动态影像 / 平面交互 / 应用开发。

**Actions**
- 点分类 → 本地筛选（支持 URL `?filter=Photography` 直达，这层是纯前端）。
- 点卡片 → 打开详情弹窗。**当前用列表里已有的数据直接渲染，不二次请求**。
  - 但如果详情（尤其图集）很重，改成"列表只返回摘要、点开再取详情"我也接受 —— 想听后端的意见。
- 弹窗内点图 → 全屏灯箱，支持左右循环切换 + "第 N / 共 M 张"页码。
- 弹窗内点 GitHub / Demo → 新标签打开外链。
- B 站视频 → 前端用 BV 号拼官方播放器 iframe。

**States to handle**
- **Loading**：列表 loading（建议骨架屏）；详情若独立接口，弹窗内也要 loading。
- **Empty**：筛选后无结果 —— 前端目前**缺空态**，需要补。
- **Error**：列表 / 详情拉取失败。
- **Special（封面三态）**：
  1. 有封面图 → 显示图片，hover 放大
  2. 无图但有 B 站 BV 号 → 显示播放按钮 + "Video Preview"
  3. 都没有 → 显示标题占位 + "预览部署中… / Preview Deploying…"
- **Special（获奖块）**：获奖为"无"时不展示。⚠️ 前端现在是靠字符串匹配 `'暂无获奖' / '无' / 'None'` 判断的，**这个约定很脆弱**，希望改成空数组或布尔标记（见 Questions）。

**Business rules affecting UI**
- 摄影类（Photography）卡片不显示标签行；开发类（Development）走图标卡片样式，不用封面图。
- 分类固定顺序：摄影 → 动态影像 → 平面交互 → 应用开发（前端写死）。
- 作品顺序目前等于数据文件里的顺序，**希望后端提供排序字段 / 支持置顶**。

### 5. 文章页 Articles（`src/views/articles/index.vue`）

**Purpose**：文章列表 + 分类侧栏筛选 + 日期排序。

**Data I need to display**
- 页面标题 + 描述（中英）。
- **文章列表**，每篇需要：稳定 id、分类、外链地址、封面图（可空）、发布日期、双语标题。
- **分类列表及其中英文案**。分类当前 5 个：`DiT` / `LUNA` / `瞎叨be叨` / `After8` / `山海疗养院`。
  - 文案是带 `|` 的复合形式（如 `DiT | 数媒与课程`），前端**只取 `|` 前部分做封面角标**，全量做筛选按钮文案。这个"靠 `|` 截断"的约定也挺脆弱，见 Questions。

**Actions**
- 点分类 → 本地筛选。
- 点"时间排序"按钮 → 本地升序 / 降序切换（默认降序，最新在前）。
- 点卡片 → **新标签打开外链**（当前所有文章都跳微信公众号，站内没有正文页）。

**States to handle**
- **Loading**：列表 loading。
- **Empty**：已有空态文案「暂无文章 / No articles found」。
- **Error**：列表拉取失败。
- **Special**：日期缺失时前端显示 `No Date`。希望后端保证日期必填，或明确告诉我们可空。

**Business rules affecting UI**
- 需要展示"共 N 篇文章"（筛选后的数量）。
- 文章数量未来可能增长 → **是否需要分页 / 无限滚动？** 目前是前端一次性全量排序（见 Questions）。

## 非功能性需求

- **双语**：是"按语言参数返回单语"还是"一次返回 zh / en 两份"？前端切语言时不希望重新发请求（会闪）。
- **图片**：希望返回可直出的绝对地址。摄影图集单项目可达 50 张，**希望有缩略图 / 原图两档**，或至少 CDN 支持尺寸参数（灯箱用原图，网格用缩略图）。
- **防盗链**：微信图片有 referer 校验，前端现在靠 `referrerpolicy="no-referrer"` 绕过。**如果后端转存图片就没这个问题**；如果继续用外链，请确认图片服务允许无 referer 访问。
- **缓存**：内容更新不频繁，建议 CDN / 缓存 + ETag。前端可接受"一次性拉全量作品"的做法。
- **鉴权**：站点侧全部匿名只读即可。后台管理系统与本站接口分离。
- **错误码**：统一 `code` / `msg`，前端只做通用"弹 msg"处理，除非有需要特殊分支的错误（如内容下架）。

## Uncertainties

- [ ] 双语到底按参数返回单语，还是一次返回双语
- [ ] 作品详情是否需要独立接口（还是列表一把梭）
- [ ] 摄影图集是否随列表返回（体积顾虑）
- [ ] 文章是否需要分页 / 无限滚动
- [ ] 教育经历页是否在本次范围内
- [ ] "无获奖"的表达方式（现在是靠字符串 `'无'` / `'None'` / `'暂无获奖'` 匹配，很脆弱）
- [ ] 文章分类文案里的 `|` 截断约定是否保留
- [ ] 封面缺失 / "预览部署中…" 这个状态由谁决定（后端字段 vs 前端按空值推断）
- [ ] 音频是否走接口（需 Range 支持）还是直接给静态直链
- [ ] 微信图片等外链是否由后端转存（否则有过期风险）
- [ ] 作品分类枚举是前端写死还是后端下发
- [ ] 导航菜单拉取失败是否需要前端静态兜底

## Questions for Backend

- 全站文案能合成一个"站点配置"接口一次返回吗？还是按页面拆更合适？
- 如果语言是"按参数返回单语"，前端切语言要重新请求并会闪一下 —— **能接受一次返回双语吗**？
